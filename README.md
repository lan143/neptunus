# Neptunus

Прошивка ESP32 (PlatformIO, Arduino framework, KinCony KC868-A6) для домашней водяной станции: ввод городской воды, буферная ёмкость питьевой воды, ёмкость дождевой воды для полива и байпасс. Контроллер читает давление и уровни, управляет клапанами и насосами, держит автоматику наполнения и защитные блокировки, отдаёт данные в MQTT/Home Assistant и имеет веб-панель.

## Устройство водопровода

Ввод воды из центрального водопровода → счётчик (подключён к контроллеру navier; из этого контроллера данные с него сейчас недоступны, только если подписываться на топик через MQTT) → датчик давления → коллектор.

Отводы коллектора:

1. Ветка наполнения ёмкости для питьевой воды → сервопривод → ёмкость для питьевой воды (к ней подключён датчик уровня).
2. Ветка наполнения ёмкости для уличного водопровода → сервопривод → ёмкость для уличного водопровода (датчик уровня подключён к контроллеру Evelyn, текущий контроллер читает уровень по MQTT).
3. Байпасс в обход ёмкости для питьевой воды.

Дальше:

- Ёмкость для питьевой воды → насос домашнего водопровода → счётчик потребления домашнего водопровода → дом.
- Ёмкость для уличного полива → насос уличного водопровода → счётчик потребления уличного водопровода → уличные потребители.

```
                  Центральный водопровод
                            │
                    счётчик (navier)
                            │
                    датчик давления ◄── WB-MAI6, канал 1
                            │
                        коллектор
          ┌─────────────────┼──────────────────┐
          │                 │                  │
      ветка 1           ветка 2            ветка 3
          │                 │               байпасс
    сервопривод       сервопривод            │
          │                 │                  │
   ёмкость питьевой   ёмкость уличного         │
   воды (+QDY30A)     водопровода (+Evelyn)    │
          │                 │                  │
   насос домашнего    насос уличного           │
   водопровода        водопровода              │
          │                 │                  │
   счётчик домашнего  счётчик уличного         │
   потребления        потребления              │
          │                 │                  │
         дом         уличные потребители       │
                                              └──► в дом (в обход ёмкости)
```

**Следствие, на котором держится автоматика:** при закрытом байпассе потребление в доме черпает из бочки и вообще не касается линии ввода/датчика давления; уличное потребление тоже. Через датчик давления проходят только заборы на наполнение ёмкостей и забор через открытый байпасс.

## Железо и подключение

- KinCony KC868-A6: ESP32 + Ethernet.
- I2C: SDA = 4, SCL = 15. PCF8574 входов — 0x22 (импульсы счётчиков), PCF8574 реле — 0x24.
- RS485: TX = 27, RX = 14 (Serial2). Modbus, скорость задаётся в настройках, по умолчанию 9600.
- WB-MAI6 (адрес по умолчанию 2) — давление в подводке, канал 1. Рассчитанные значения валидируются: sentinel-ошибки 0x7FFF, 0xFFFF, 0xFFFE и значения вне калибровки отбрасываются. Сохранённая таблица регистров лежит в корне репо (ссылка ниже).
- QDY30A (адрес по умолчанию 1) — уровень бочки питьевой воды.
- Счётчики: домашний — вход 0 входного расширителя, 10 л/импульс; уличный — вход 1, 1 л/импульс. `isFlowOfWaterActive()` остаётся true ещё 120 с после последнего импульса.
- Безопасное состояние при загрузке и во время OTA — маска `0xEC`: все три клапана закрыты, все насосы выключены. PCF8574 после подачи питания выдаёт 0xFF (клапаны открыты), поэтому маска пишется в расширитель как можно раньше.

Каналы реле:

| Канал | Назначение | Логика |
|---|---|---|
| 0 | клапан наполнения бочки | открыт = реле выключено |
| 1 | байпасс | открыт = реле выключено |
| 2 | насос уличного водопровода | включён = реле под напряжением |
| 3 | дренажный насос | включён = реле под напряжением |
| 4 | клапан наполнения уличной ёмкости | открыт = реле выключено |
| 5 | насос домашнего водопровода | включён = реле под напряжением |

Каналы насосов 2/5 поменяны местами под реальную разводку. Клапаны нормально-закрытые с «open semantics»: реле выключено — клапан **открыт**, включено (LOW, под напряжением) — **закрыт**.

## Возможности автоматики

Пороги и константы собраны в `src/automation/automation.h` и чистых заголовках `src/automation/*.h`.

**Тики и свежесть данных**

- Два тика: 10-секундный тик давления (плохое давление, debounced bypass-режим, тренды уровней) и 1-секундный тик решений (всё остальное).
- Датчики читаются с окнами свежести: давление — 30 с над 10-секундным опросом, уровень бочки — 30 с над 1-секундным опросом. Протухшие данные трактуются консервативно.

**Наполнение бочки и аварийный режим**

- Гистерезис наполнения: вкл при 40 % диапазона (0.37–1.2 м), выкл при 95 %. Перелив закрывается принудительно при ≥ 1.2 м в любом режиме.
- Аварийный режим держится на счётчике плохого давления (10-секундные выборки с давлением < 1 бар или невалидным, насыщается на 24): когда счётчик превысит 12, режим активен, если выполняется хотя бы одно. Валидные чтения выше 1 бара сбрасывают счётчик по одному, а идущий забор (через открытый байпасс или progressing-залив) удерживает его на месте.
  - ни один клапан наполнения не открыт и нет объяснения в виде байпасс-забора (байпасс открыт + есть потребление в доме);
  - открытый клапан наполнения «стоит»: уровень не растёт по окну тренда ~10.6 мин и не находится у максимума (бочка — в пределах 5 см от 1.2 м, уличная ёмкость — у целевого уровня заливки).
- При аварии бочка наполняется до порогов 0.96/1.08 м. Потребление дома при закрытом байпассе и весь уличный счётчик аварию никогда не учитывают.

**Байпасс-режим**

- Debounced bypass-режим: EMA давления (alpha 0.1) > 3.2 бар 300 с подряд → байпасс открыт + домашний насос выключен (экономия электричества).
- Выход: EMA < 3.0 бар или быстрое падение < 2.8 бар два сэмпла подряд.
- Вход подавляется, пока активен расход по домашнему счётчику (120-секундный хвост); выходы при этом продолжают работать.

**Электросеть (finedog)**

- Состояния NORMAL/GENERATOR/BATTERY/CRITICAL; при молчании издателя > 600 с — failsafe SHUTDOWN.
- BATTERY: домашний насос работает при низком давлении и разрешённом уровне бочки; при > 1.5 бар байпасс открывается, насос выключается. Если уровень бочки не разрешает работу насоса, действует безопасный отказ: оба насоса выключены, байпасс открыт.
- CRITICAL или протухшие данные: оба насоса выключены, байпасс открыт. После выхода из переопределения состояние насоса улицы восстанавливается.

**Залив уличной ёмкости**

- Сессия с ограничениями: старт при уровне ниже 10 %, стоп на целевом уровне, максимум 1800 с и кулдаун 600 с после принудительного завершения.
- Приоритет бочки: клапан уличной ёмкости не остаётся открытым, пока открыт клапан бочки. Пауза при минимальном уровне бочки.
- Протухшие данные Evelyn закрывают клапан.

**Защиты**

- Минимальный уровень бочки 0.37 м с гистерезисом 0.07 м — для домашнего насоса.
- Протухший уровень бочки → клапан наполнения закрыт + домашний насос выключен.
- Насос улицы: яма < 8 % — выкл, > 10 % — возврат (только авторежим); протухшие данные ямы → выкл; холостой ход (< 2 л за 600 с) → выкл; максимальный непрерывный пробег 7200 с → выкл.

**Ручной режим**

- Реле управляются пользователем, но все защитные принудительные действия (перелив, минимальный уровень, холостой ход, максимальный пробег) действуют и в ручном режиме; защита по устаревшим данным уровня — только в автоматическом.
- Авторежим и состояние дренажного насоса сохраняются в LittleFS и переживают перезагрузку.

## MQTT и Home Assistant

Топики: `neptunus/<chipid>/<entity>/state` и `/set` (команды). HA discovery включён настраиваемым префиксом.

- Сенсоры: `water_consumption`, `yard_water_consumption`, `barrel_water_level`, `water_pressure_supplier`.
- Бинарные сенсоры: `emergency_mode`, `barrel_level_stale` (уровень бочки устарел).
- Реле/переключатели: `filling_barrel_valve`, `bypass_valve`, `rainwater_pit_valve`, `home_pump_station`, `drainage_pump`, `outdoor_pump_station`, `auto_mode`.

Клапаны используют open semantics: **on = ЗАКРЫТ**, off = ОТКРЫТ. Это относится и к HA, и к веб-панели.

Внешние интеграции по MQTT:

- Уровень уличной ёмкости приходит от Evelyn. Топик задаётся в настройках «rainwater»; пустой топик = фича выключена. `rainwaterPitMaxHeight` по умолчанию 1.6 м, цель заливки — 20 %.
- Состояние электросети приходит от finedog (`finedog/electricity`): NORMAL/GENERATOR/BATTERY/CRITICAL.

## Сборка, прошивка, тесты

```sh
pio run -e kc868a6          # сборка
pio run -e kc868a6_ota      # прошивка по OTA
```

Адрес OTA — в `platformio.ini`; пароль задаётся в `platformio.ini` / настройках контроллера.

Все зависимости запинены на точные версии/SHA в `platformio.ini`: чистая пересборка не должна зависеть от HEAD библиотек. CI (`.github/workflows/build.yml`) собирает прошивку с холодным кэшем и прогоняет хост-сценарии.

Тесты — автономные хост-сценарии в `test/*.cpp`, живут вне `src/`, чтобы PlatformIO никогда не компилировал их в прошивку. Сейчас четыре набора: `bypass_mode`, `level_trend`, `wb_mai6_pressure_validation`, `emergency_mode` — всего 48 сценариев. Команда каждого описана в шапке файла, общий вид:

```sh
g++ -std=c++17 -Wall -Wextra -Werror -fsanitize=address,undefined \
    test/<suite>.cpp -o /tmp/<suite> && /tmp/<suite>
```

## Логи

Логи уходят по сети на `192.168.1.2:5555` (`/_bulk`) и смотрятся в Loki/Grafana на `192.168.1.2:3000` (инстанс Neptunus). Адрес и порт логов настраиваются.
